# Guest intents (roadmap step 8, FULL-SYNC-PLAN 3.7)

Campaign fix wave 1 (P4, CAMPAIGN-GAPS G03 / G04 / G10 / G35): per-frame OnTrigger and OnStartCombat forwarding, a picked-up note goes to the journal, per-player gear stashes on the shared storage containers, and `nvcoop_intents.json` exists. Still code only: none of it has run in a game (section "Needs in-game proof").

Owner: guest-intents agent. **Everything here is unit-tested game-free. Nothing has run in a game.** The x86 glue compiles into `nvcoop.dll` and stays
inert until `nvcoop.ini` `[intents] enable=1`.

What it does: every interaction a guest has with the shared world (activate, trigger enter / leave, pickup, hit, dialogue start, terminal use,
container open / close) is forwarded to the host as an **intent**. The host runs the real interaction inside a capture scope with the acting-player
context set to the guest's **puppet**, and commits whatever comes out with the guest as the txn origin. Rewards (`Recipient::origin()`) therefore
reach the guest and only the guest, and `player` inside every script block that runs is the guest's puppet, not the host.

```
plugin\intents\run_tests.cmd        # build (shared tree build\all) + 77 tests + 50 runtime twins + proof self-test + pin regeneration check; prints ALL OK
python -I plugin/intents/tools/intents_proof.py --instances 0 1 2 --door .. --item .. --item-base .. --container ..    # in-game, NOT RUN
```

references are too far apart. `--no-position` skips it, `--radius N` changes the 400.

## How a guest interaction travels

```
guest   L5 activate / script-event observer  ->  IntentClient.decide  ->  Intent on 0x8D  (local call goes on, or is suppressed for pickups / triggers)
host    Mux handler -> IntentHost.handle: joined? new id? rate? kind on? target loaded? acting actor? in reach?
        -> Runtime::runAsGuest(slot, ...)  [origin forced, acting hook on]
              -> IIntentEngine::beginActing(puppet, slot, Cause{Intent, target, kind})   [ActingPlayerScope + ScopedCapture]
                    activate / raiseEvent / runTerminalEntry / disableRef + record(AddItem origin)
           (scope closes: the txn is emitted with the guest as origin)
        -> Verdict on 0x8D back to the guest
```

| Kind | Guest decision | Host action |
|---|---|---|
| Activate (door, switch, lever, furniture, terminal) | forward, local call goes on (animation, menu) | engine `Activate` with the puppet as activator inside the scope (OnActivate blocks run with `player` = puppet) |
| PickUp (world item) | forward, **suppress** the local pickup | first claim wins (`Taken` for everyone else); the item ref is disabled and an `AddItem{base, count, origin}` is recorded; `OnAdd` blocks run as the puppet. Nothing touches any actor's inventory. **A NOTE** (`TargetInfo::note`: the base form is a note or holotape) is not an inventory item: the host's journal gains it through `IIntentEngine::addNote` (console `AddNote`, so `GetHasNote` on the host is true and the engine's AddNote hook records the shared `AddNote` effect into the scope; the guest and every other copy get it from that txn), no `AddItem` (G10). The note is added BEFORE the ref is disabled, so a refusal leaves it lying there |
| ContainerOpen (chest, dead body) | forward, local menu goes on | one user at a time (`Busy` + holder), 120 s lease, released by ContainerClose, the leaver, or the lease; the OnActivate half runs as the puppet when there is one. Shared storage ids in `nvcoop_intents.json` are answered with a per-slot container the guest opens instead |
| TriggerEnter / TriggerLeave | forward, **suppress** the local event | `MarkBaseExtraListScriptEvent(host player 0x14, trigger, mask)` inside the acting scope, then the trigger's own script is run at once (follow-ups 1, below); 800 ms per-player cooldown against re-fires. A successful Enter starts a **presence** (below) |
| TriggerStay (`[intents] trigger_stay=1`, default on) | the guest's per-frame `OnTrigger` events become one keep-alive per `stay_keepalive_ms` (1000), the local event is suppressed | the host keeps a presence per (player, trigger) and raises `OnTrigger` for that player itself (same rule as Enter: the host player's reference as the event's object, the script run now) on every host frame (`tick`, or every `stay_raise_ms`) until TriggerLeave, the player leaving, the volume going away, or `stay_lease_ms` (3500) without a keep-alive. At most `stay_max` (64) presences. No stash swap on these per-frame runs (G04) |
| StartCombat (`[intents] combat=1`, default on) | an actor started combat with THIS guest's player (`OnStartCombat`, mask 0x8000, actor target only): forwarded, the local event goes on | the actor's `OnStartCombat` blocks that filter on `player` run once with the puppet as `player`; a dead actor is `Denied`, a non-actor `BadTarget`; 800 ms per-(player, actor) cooldown. The combat itself rides the combat and actor channels (G04) |
| Hit (`[intents] hit=1`, off by default) | forward, local goes on; actors are never forwarded | OnHit on non-actors only; the combat channel raises OnHit for actors, a second path would run the blocks twice |
| TerminalUse | the `TerminalEntryRun` hook computes the entry's index path and forwards; local call goes on | the entry's result script runs with the puppet acting (`TerminalEntryRun`, pinned) |
| SetStage (`[intents] stage=1`, default on) | the guest's `SetStage` detour used to drop a script / console stage advance silently (suppress_policy.h rule 3: the host owns quest progress). It now hands the dropped call to the intents client, which sends `Kind::SetStage` (target = quest, value = stage; one intent per (quest, stage) per `coalesce_ms`). Nothing is applied on the guest | the stage must be an advance (`NoAdvance` when the quest is already at / past it: no second run of result scripts); `allowStage` asks the rules engine's ExclusiveStages (`Denied`, a loser is refused BEFORE its scripts run); then the real `setstage` runs under the guest's acting scope through the normal detour, so the stage gate answers barrier / tether (`Deferred`: the host releases it itself later). Every refusal is a counter (`intents.status` service.detail.stage) and a log line `intents: guest stage ... not run: <why>` |
| DialogueStart (`[intents] dialogue=1`, off by default) | routed to the 0xD1 dialogue adapter (`DialogueNode::requestStart`), never run as an activation | pre-flight verdict if sent on 0x8D: Denied for a dead NPC |

### Script events for a guest (follow-ups 1, item 1)

A guest's `OnTrigger` / `OnTriggerEnter` / `OnTriggerLeave` / `OnAdd` / `OnStartCombat` / `OnHit` is a **flag** in the target's script event list (`MarkBaseExtraListScriptEvent` @0x5AC750 ORs the mask into the entry of the event's object and into the entry of "any object"); the block runs when the engine next runs the reference's own script (`Script::Execute` @0x5AC1E0, which clears the list), on its next update. Two things made the first version of this path do nothing for the Dead Money return trigger (`OnTrigger Player`):

* the object was the puppet, and a block that names `Player` compares the object of the event with the player reference. The host now marks the event for **0x14** and lets the acting scope say who `player` is;
* the run came later, with no scope open, so `player`, the origin of everything the block did and the gear stash window were the host's. `IIntentEngine::runScript` now runs the target's script (its ExtraScript: script + event list) **inside the scope**, right after the mark. A mark the host's own player (or anybody) left pending in the same list is run first, outside the scope (`eventPending` / `runScript`), because a run consumes every mark of the list.

`status.events.scriptRuns / scriptMissed / flushed` count the three. The legacy story-channel executor in coop_module.cpp (`TriggerEnter ... not drivable yet`) is only the path when `[intents]` is off, in which case a guest forwards no trigger at all. In-game proof is the Dead Money return trigger (a guest's gear comes back from its own stash order) and any `OnTrigger Player` block.

### The stand-in retry (follow-ups 1, item 2)

An activation that recorded nothing for the puppet is redone once by the host's own player (`GetActionRef == player`: the Broc flower, the Xander root), and what that player gained is taken back from the host. The second run is only safe for scripts that leave no host-local trace, so it is **data**: `retryScripts` in `nvcoop_intents.json`, written by `tools/gen_intents_data.py` from `out/questdata/scripts.json.gz` (28 scripts: every object script with an OnActivate that tests `GetActionRef == player` / `IsActionRef player`, no block but OnActivate / OnLoad / OnReset, and only commands the capture records or that touch nothing outside the world in OnActivate). The host keys it by the script attached to the reference or its base form (`TargetInfo::script`); a script that is not listed (a vending machine's message box, a switch) keeps the puppet's run alone, and so does everything without the data file. `status.standInRetries` counts the redos.

### Gear stashes (G35)

The Fort's confiscation, the barge return, the Dead Money entry strip and the Fort pit fights keep every player's gear in ONE container reference that the scripts name (`NVCCPlayerStorageREF`, `FortPlayerEquipmentContainerRef`, ...). The per-slot redirect of `container_redirect` cannot help: it needs a container form per slot (no plugin of ours adds any) and it only changes what a player's MENU opens, not what a script's `RemoveAllTypedItems` moves. So the shared container stays the only one and the host swaps its contents around every guest interaction (`IntentHost::runScoped`, and a guest conversation's result scripts in `IntentService::runDialogueResult`): before the interaction the container holds exactly that guest's stash (what it put there before), whatever else was in it (the host's gear) is parked; afterwards what the container holds is filed as that guest's stash again and the parked contents come back. Scripts need no change and see only their own player's gear. The host's own player (slot 0) is never swapped: the container's real contents are the host's. Containers nothing is stashed in and that are empty cost one read.

The swap is not a change of the world: `IIntentEngine::replaceItems` mutes the capture hub and runs outside the acting scope, so no `RefAddItem` / `RemoveAllItems` travels. A container that cannot be read or rewritten is left alone and counted (`stash.failed`); a failed read on the way back assumes the guest's stash unchanged and still returns the parked contents. The ledger lives in `IntentService::stash()` (outlives sessions) and is written to `nvcoop_intents_state.json` next to the dll every 2 s when it changed, and read at start. `[intents] storage=0` switches it off.

Limits: the ledger keeps item and count only (condition, ammo load, ownership and other extra data of a stack are not kept); only containers with an EMPTY base inventory belong in the list (the engine read sees changes relative to the base inventory); the Tops / Ultra-Luxe / Silver Rush / Gomorrah friskings and the Honest Hearts gear boxes are not named by any script in the data, so they are not in the file (add an EditorID to `tools/gen_intents_data.py` when a scan finds the script that fills them); script runs that are NOT a guest interaction (a host quest script that strips the host's player) see the container as it is, so the party-wide steps of those quests still need the rules engine's PerPlayerScene / PartyWarp work (P1) and the capture of a player's `RemoveAllItems` with its destination (P2, docs/handover/P4-requests.md).

**Who acts for the guest (host side):** the guest's puppet (plugin/avatar, through `livewire::glueAvatarRef`), else NV:MP's ghost, else the host's own
player as a **stand-in** (policy limited): `Activate` as the host's player would pop a menu on the host's screen for containers, terminals, NPCs
and unknown targets, so the stand-in is refused (`NoPuppet`) for those unless `standin_unsafe=1`. The v1 behaviour of coop_module (stand-in for
everything) is gone as soon as `[intents] enable=1`: the service takes the story-channel executor over, so `forward_activate=1` guests get the same
checks. Reach is checked against the puppet only (the stand-in's position is meaningless) and only when both positions are known.

**Guards:** per-player token bucket (`rate_burst`, `rate_per_sec`), exactly-once ids per session (a duplicate gets the SAME verdict again and runs
nothing), bounded claim table (`claim_memory`), leased locks, 64 intents in flight per guest, a datagram from a slot that is not a joined player is dropped.

## `nvcoop.ini`

```
[intents]
enable=0              ; master switch, default OFF (every live-layer part is)
activate=1 trigger=1 pickup=1 terminal=1 container=1
stage=1               ; SetStage: a guest's blocked quest stage advance is forwarded (guest) and judged (host)
hit=0                 ; see the table: opt-in
dialogue=0            ; DialogueStart forwarding; needs L8's engine glue (not wired in this build)
dialogue_results=1    ; host: run a guest conversation's INFO result scripts (replaces coop_module's stub runner)
standin=1             ; the host's player may stand in for a guest without a puppet ...
standin_unsafe=0      ; ... also for targets that open a menu for the player (container, terminal, NPC)
require_puppet=0      ; never stand in
trigger_stay=1 combat=1 storage=1   ; per-frame OnTrigger presence, OnStartCombat, gear stashes
check_reach=1  reach_activate=450 reach_pickup=450 reach_trigger=4000 reach_container=450 reach_terminal=450 reach_hit=6000 reach_combat=6000
stay_keepalive_ms=1000 stay_lease_ms=3500 stay_raise_ms=0 stay_max=64   ; guest keep-alive period; host lease, re-raise interval (0 = every frame), presences held
save_gate=1           ; enforce the shared SaveSuppress flag (CanSaveNow hook)
rate_burst=40 rate_per_sec=20 lock_lease_ms=120000 trigger_cooldown_ms=800 pending_timeout_ms=6000 coalesce_ms=250 claim_memory=4096
redirect_file=nvcoop_intents.json   ; default; 'none' = no data file. Holds 'redirects' (a container per slot) and 'stashes' (gear containers)
```
Environment `NVCOOP_INTENTS_<KEY>` beats the ini. Numbers are clamped; a bad boolean keeps the module off and says why (`intents.status` `note`).

Bridge RPCs: `intents.status`, `intents.submit {kind, ref, path?}` (guest), `intents.host.run {slot, kind, ref}` (host, runs an intent as if that player had
sent it: single-instance proof), `intents.cansave` (asks the engine's CanSaveNow through the gate, saves nothing).

## SaveSuppress enforcement (internal lane notes "SaveSuppress enforcement (L5)")

`SaveSuppress` was accepted and stored but nothing stopped a save. `intents_module.cpp` hooks the engine's `CanSaveNow` (0x850FE0, thiscall ret 4, pinned
from the exe, the same function the bridge's direct save asks first); the `SaveGate` returns false while `saveSuppressedBy(Runtime)` is true (guest: the
state it applied; host: its own world), at most one HUD line per 5 s. Manual save, quicksave and autosave all ask `CanSaveNow`: **assumed, not proven**
(the in-game proof step 7 checks the function itself, not each caller).

### Known limits (not hidden)
* **Stand-in slot:** while the host's player stands in, `nvhooks::actingSlot()` reads 0 (`registerPlayerSlot(0x14, slot)` would re-map the host's own player for
  good). A companion a guest recruits that way gets owner 0. With a puppet this does not happen.
* **nvhooks slot table holds 8 entries** and never forgets a ghost ref: every puppet respawn (each save load) uses one. After 8 distinct puppet refs
  `actingSlot()` falls back to 0 for new ones. Needs `ActingContext::clearSlots()` exposed by L5 (`nvhooks::clearPlayerSlots()`), then call it from the
  module on `PostLoadGame`. Not done here (L5's files).
* **Disabled flag:** `kGoneFlags` uses 0x800 (GECK "initially disabled"), which is not in xNVSE's header. A wrong bit only costs the `Taken` verdict
  for an item the HOST picked up itself; guests are still protected by the claim table (there is a test where the flag is invisible).
* **Combat flag:** `TargetInfo::inCombat` is always false (no verified flag), so `DialogueStart` denies dead NPCs only.
* **Container contents** (take / put) are the loot lane's; this module owns the open / close lock and the OnActivate half.
* **DialogueStart** only reaches the 0xD1 adapter; L8's `EngineGlue` (talk veto, topic list, INFO pick) is not instantiated in the plugin, so a guest conversation
  is not end to end. See the wiring ledger.
* **Terminal hook** is installed on the first guest session, not at load; a terminal pick before that is not forwarded.
* `OnAdd` / `OnOpen` / `OnClose` events are deliberately not forwarded (covered by the pickup and container flows). The every-frame `OnTrigger` is now a presence the host re-raises (TriggerStay above); whether the guest's engine raises `OnTrigger` through `MarkBaseExtraListScriptEvent` with the local player as the object is unproven. A host-owned NPC that starts combat with a guest's puppet on the HOST raises no event the guest sees: the host-side observer for that is a request to P2 (docs/handover/P4-requests.md).
* Per-frame `OnTrigger` raises run without the gear stash swap (cost); a trigger script that moves gear between a player and a stash container sees the real container.
* A note picked up through the loot module (`[loot] enabled=1` sets `[intents] pickup=0`) is the loot module's claim path; it must grant `AddNote` for a NOTE base too (request in docs/handover/P4-requests.md).
